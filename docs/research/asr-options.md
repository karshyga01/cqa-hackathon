# Загрузка аудио → расшифровка → оценка: что выбрать

*Записку подготовил Claude (Anthropic). Ни с одним поставщиком распознавания речи Claude не связан. Данные взяты с официальных страниц на 2026-11-07, поверх них применены поправки проверки фактов. Платные API не вызывались, на машину ничего не ставилось.*

## 1) Итог
- Звонки организаторов записаны в моно (16 кГц, 4–7 мин), поэтому разделить собеседников по каналам стерео не получится. Нужен сервис или модель, которые сами различают голоса.
- Казахский, русский, пословные метки времени и разделение голосов по официальным данным есть у ElevenLabs Scribe v2, MAI-Transcribe-2 и Deepgram Nova-3 (последний не берёт смесь kk/ru в одном звонке). Все три доступны через ключ OpenRouter, который уже есть. Из региональных то же есть у Yandex SpeechKit в регионе Казахстан (kz1). Из локальных лучший заявленный казахский у GigaAM-Multilingual.
- Неизвестно: качество на смеси kk/ru и на телефонном звуке 8 кГц (нигде не опубликовано), доступ из Казахстана у большинства облаков (официально подтверждён только у OpenAI и Gemini API), скорость на RTX 3050 Ti.
- Цифры WER от разных поставщиков посчитаны по разным методикам, напрямую их сравнивать нельзя.

Отброшены:
- Speechmatics и китайские облака — нет kk.
- Sber SaluteSpeech — с 15.07.2026 не подключает новых клиентов.
- OpenAI gpt-transcribe — не различает собеседников; старые модели отключат 26.02.2027.
- AssemblyAI — kk с WER 25–50%.
- NeMo-модели kk-ru (NVIDIA FastConformer kk-ru, nur-dev kk-ru-asr-tdt) — NeMo официально не работает на Windows; у nur-dev вдобавок лицензия только для некоммерческого использования.
- Разделение по стерео-каналам — DEV-звонки в моно; оставить только как ветку «если файл стерео».

## 3) Варианты на выбор

**A. Облако через уже имеющийся ключ OpenRouter.** Основной — `elevenlabs/scribe-v2`, для сравнения — `microsoft/mai-transcribe-2`. Включить `provider.zdr=true` и разделение голосов через `provider.options`.
- (+) Новых аккаунтов не нужно. Есть слова, метки и собеседники. Цена — центы за звонок.
- (−) Персональные данные уходят в облако США, нужно согласие или анонимизация.
- (−) Таймаут 60 с может потребовать резать запись. После нарезки метки собеседников между кусками не совпадают, роли придётся сопоставлять заново.
- Время: ≈10–15 ч, из них 4–6 ч — сама загрузка и хранение файла.

**B. Локально.** Отдельный Python-процесс на 127.0.0.1 (не порт 3000): onnx-asr + GigaAM-Multilingual large CTC + VAD (нарезка по паузам), голоса — sherpa-onnx с `num_speakers=2`. Звук в WAV 16 кГц моно переводит браузер, поэтому ffmpeg не нужен.
- (+) Данные не покидают ноутбук, 0 $, лучший заявленный казахский.
- (−) Нужна установка: onnx-asr, onnxruntime-gpu, sherpa-onnx; сборки под Python 3.14 на PyPI есть. Нет пунктуации. Скорость на 3050 Ti не подтверждена: по моей оценке 10–30 с на 10 минут звука, плюс десятки секунд на разделение голосов.
- Время: ≈14–20 ч (моя оценка; для варианта с torch и pyannote интеграция оценивала 18–28 ч).
- Облегчённая ветка B′: всё в Node через `sherpa-onnx-node`, без Python. Но только русский (GigaAM v3 или T-One).

**C. Через чат-модель.** Gemini 3.1 или 3.5 Flash-Lite через OpenRouter: аудио в base64, ответ в виде JSON-схемы.
- (+) Встраивается быстрее всего: ≈8–12 ч, большую часть уходит на подбор промпта. ≈$0.002/мин.
- (−) Метки и роли — это текст модели, а не выравнивание по звуку. Есть открытый баг о том, что метки «уплывают» к концу записи. Казахский не подтверждён. Vertex хранит помеченные запросы до 90 дней.
- Годится для прототипа, но не для точной перемотки по меткам.

## 4) План интеграции в наш сервер
1. **Загрузка.** Новый маршрут `POST /api/upload/audio`. Тело — сам файл (`xhr.send(file)`, прогресс через `upload.onprogress`). На сервере поток пишется в `data/audio/*.tmp` с лимитом 100 МБ, затем проверка `looksLikeAudio` и `renameWithRetry`. В `audio.json` записывается `{file, bytes, mime, source:'upload'}`.
2. **Исправления в `audio.js` и `server.js`.** Расширение и MIME брать из записи (сейчас всегда `.mp3` и `audio/mpeg`). `status()` сначала смотрит meta, потом `audio_url`. Кнопка удаления и срок хранения файла.
3. **Подготовка звука в браузере.** `decodeAudioData` → если 2 канала, разделить → WAV 16 кГц моно → нарезка, если ASR требует.
4. **Очередь задач.** По одной задаче за раз. Состояния `queued / transcribing / mapping / evaluating / done / error`, хранение в `data/jobs.json`, браузер опрашивает `GET /api/jobs/:id`. Незаконченные после перезапуска помечаются `interrupted`.
5. **Адаптер ASR.** `transcribe(wav, {langs:['kk','ru']}) → [{start, end, speaker, text}]`, реализации: openrouter-stt, локальный процесс, gemini. Сегменты склеиваются в реплики: тот же собеседник и пауза меньше 1 с — одна реплика; новая — при смене собеседника или паузе больше 2 с. `timestamp = formatClock(end)`, как у организаторов, плюс `start_sec / end_sec`. `normalize.js` должен их пропускать.
6. **Кто оператор.** Баллы по фразам «Freedom», «меня зовут», «чем могу помочь», «сізге қалай көмектесе аламын» и по тому, кто заговорил первым. В карточке — кнопка «Поменять роли» и пометка «роли определены автоматически». Запасной вариант — запрос к LLM, по умолчанию выключен.
7. **`timeline.js`.** Если у реплики есть `start_sec / end_sec`, брать их напрямую, без `END_LAG_SEC`, без оценки по символам и без `bestShift`.
8. **Оценка.** Текущий пайплайн без изменений.

## 5) Живой тест на 1–2 записях
- Взять 1–2 DEV-mp3 с эталонной расшифровкой организаторов, по возможности с казахским (есть ли он в DEV, неизвестно). Прогнать Scribe v2, MAI-Transcribe-2 и Flash-Lite. Стоимость: 7 мин × 3 модели — меньше $0.1.
- Проверить, проходит ли 7-минутный файл через OpenRouter без нарезки (таймаут 60 с).
- Проверить, приходит ли поле `speaker` в `verbose_json` при `zdr=true`.
- Сравнить с эталоном: долю реплик, приписанных не тому собеседнику; сдвиг меток (особенно к концу звонка у Gemini); заметные ошибки на смеси kk/ru.
- Понизить тот же файл до 8 кГц в браузере, отправить ещё раз и посмотреть, насколько упадёт качество.
- Бесплатно, если разрешите установку: GigaAM-Multilingual + sherpa-onnx на тех же файлах — скорость на 3050 Ti и сравнение текста.
