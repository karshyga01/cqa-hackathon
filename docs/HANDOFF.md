## 1. Задача (кратко)

Хакатон Freedom Broker «CQA» на 24 часа. Нужен прототип, который оценивает диалоги операторов поддержки (чаты и звонки, RU/KZ/EN) по чек-листу из 8 критериев с помощью ИИ, объясняет оценку репликами-доказательствами, поддерживает N/A и апелляции. Интерфейс на HTML/CSS/JS, чтобы потом встроить в Dynamics 365.

**Сроки:**
- Через 23 ч от старта организаторы выдают **контрольный набор** (другой `group_id`) и просят **заменить один критерий через интерфейс** и переоценить.
- Через 24 ч — стоп-код: **публичный** git-репозиторий с README. Защита 5 минут.

**План защиты (5 минут):** 1 мин интерфейс и диалог; 2 мин оценка ИИ, объяснения, переход к реплике, пример N/A, итог; 1 мин апелляция → решение → новый итог; 1 мин замена критерия и переоценка. Назвать модель и цену одной оценки.

**Данные DEV:** 65 диалогов (60 чатов, 5 звонков), 35 RU / 15 KZ / 15 EN. Загрузка в интерфейсе: код набора `DEV`.

### Ответы организаторов (Telegram, 07.11)
1. Сравнивают с эталоном **по ответу на каждый критерий** (Да/Нет/N/A/ступень), не только по итогу.
2. Контрольный набор — **10 транскриптов, только чаты**.
3. Замена критерия на контроле: «как бы вы это сделали?» (веса — наше решение). **Уже оценённые контрольные диалоги нужно переоценить — да.**
4. Звонки: если приветствие не попало в запись — **N/A**.
5. Идентификация (ФИО + телефон или кодовое слово/ИИН): «как бы вы реализовали?» — наше решение.
6. База знаний у организаторов есть, нам её не дали. Система — индикатор «что-то пошло не по сценарию»; без базы оцениваем логику, факты не выдумываем.
7. Округление: половина вверх до 2 знаков (50,625 → 50,63) — подтверждено.

Общий подход организаторов: идеального совпадения не ждут; важны осмысленность, обоснованность и **воспроизводимость**; N/A, грубые ошибки и неполные данные — разумно; при нехватке данных **не выдумывать**. Ценят удобство интерфейса, полноту процесса, интересные доп. возможности и технический подход.

## 3. Как устроено (что нельзя ломать)

- **Сервер:** Node 18+, без сторонних пакетов (`http`, `fs`). Слушает только `127.0.0.1`. Нет CORS `*`, проверяется Origin, POST только JSON.
- **Хранилище:** JSON-файлы в `data/` через `JsonStore` (атомарная запись, очередь изменений). `data/` в git не попадает.
- **Исходные транскрипты не меняются.** Метки времени хранятся как пришли.
- **Звонки:** метка реплики = **конец** фразы (отставание ~0,7 с); ноль записи = событие «Запись и транскрибирование запущены»; пауза записи оставляет в mp3 ровно ~5 с тишины. Калибровка в `timeline.js`.
- **Баллы считает только `scoring.js`**, не ИИ. Итог в интерфейсе всегда пересчитывается по той версии чек-листа, по которой была оценка.
- **Оценка неизменяема:** каждая оценка дописывается в историю (`data/evaluations.json`), старые не переписываются.
- **Чек-листы версионные:** каждое сохранение — новая версия; удалённый чек-лист скрыт, но старые оценки по нему открываются.
- **Апелляции:** решения в `data/appeals.json`, оценка ИИ не трогается. Финальный итог = `score(версия чек-листа, ответы ИИ + новые ответы из решённых «Изменено»)`. Новая оценка диалога закрывает открытые апелляции старой (статус `stale`). Подаёт только аналитик, решает только проверяющий (проверяется и на сервере; входа нет — роль переключается в меню).

### Оценка ИИ (шаг 5) — детали
- Модель `deepseek/deepseek-v4.1-flash-1017` (закреплённая версия) через OpenRouter, провайдер `together`, `allow_fallbacks:false`, `require_parameters:true`, `zdr:true`, `data_collection:'deny'`, `temperature:0`, `reasoning.effort:medium`, `max_tokens:16000`. Настройки в `.env` (`OPENROUTER_*`, см. `.env.example`).
- Один запрос на диалог по всем критериям. Инструкция на английском, чек-лист на русском, объяснения по-русски, цитаты дословно на языке оригинала.
- JSON-схема строится из чек-листа: по каждому критерию `evidence[{turn, quote}]`, `checked_range`, `na_reason`, `explanation`, `answer` (только допустимые значения), `confidence`.
- Проверка `validateAnswers`: реплика существует, цитата есть в реплике (соседняя — номер поправляется), для «Нет» указан участок, для N/A — условие, пустая цитата не считается.
- Не прошедшие проверку критерии переспрашиваются **один раз**; не помогло — пометка «нужна проверка человеком».
- **Отпечаток (fp)** каждого ответа: диалог + текст критерия + общие правила + модель + провайдер + глубина рассуждения + канал + язык. Совпал — ответ берётся из прошлой оценки без запроса. Поэтому **после замены критерия спрашивается только он**; изменение веса запроса не вызывает. «Оценить заново» в карточке = спросить всё.
- Цена считается по `usage.cost` от OpenRouter, включая неудачные попытки. Массовая оценка — 8 параллельно, остановка при «нет денег» или неверном ключе.
- **Замеры на реальной модели:** чат $0,002–0,007 и 5–13 с; звонок ~$0,01; 65 диалогов ≈ $0,35. На 7 диалогах все цитаты прошли проверку с первого раза.

1. Оценить ИИ все 65 диалогов («Диалоги» → выбрать все → «Оценить выбранные»).

### Шаг 9 — контроль и защита (~1–1,5 ч)

3. Учесть ответ организаторов: в звонках приветствие не попало в запись → N/A (сейчас у «Установления контакта» N/A запрещён в чек-листе по умолчанию — обсудить с пользователем).
4. README: запуск, `.env`, архитектура, модель и цена, ограничения.
5. Перед открытием репозитория: перенести ссылку API организаторов из `server/config.js` в `.env`; проверить, что `data/` и `.env` не в git.
6. По команде пользователя: коммит, пуш, сделать репозиторий **публичным**, отправить ссылку организаторам.
7. После хакатона: удалить ключ OpenRouter и создать новый (он засветился в чате).

## 5. Идеи (делать только по команде, каждую — отдельным переключателем, чтобы сравнивать «с ней и без неё»)

Идеи для точности:
1. **Гибрид:** факты из данных находит код (событие «личность подтверждена», паузы по меткам времени, закрытие чата, первая реплика оператора) и передаёт ИИ готовыми; ИИ судит только смысл.
2. **Честное «не уверен»:** низкая уверенность, расхождение при повторе, грубая ошибка → «нужна проверка человеком», а не случайный балл. (Частично есть.)
3. **Замер точности:** пользователь размечает 16 диалогов вручную (5 RU, 5 KZ/смесь, 3 EN, 3 звонка) до того, как смотреть ответы ИИ; считаем совпадение по критериям, путаницу «Нет/N/A», отклонение итога. Показать на защите.
4. **Улучшение промпта по ошибкам** на этих 16 диалогах.
5. **Сравнить инструкцию на английском и на русском** (~$0,2) — оставить лучшую.
6. **Апелляции как примеры для ИИ:** решённые апелляции подставлять в промпт как образцы.

Бонусы:
7. **Загрузка своего аудио → распознавание → оценка.** Исследование: `docs/research/asr-options.md`. Звонки организаторов в моно → нужен сервис с разделением голосов. Варианты: облако через тот же OpenRouter (`elevenlabs/scribe-v2`, `microsoft/mai-transcribe-2`; ~$0,002–0,004/мин; записи уходят в США) ~1,5–2,5 ч; локально GigaAM-Multilingual + sherpa-onnx (Python, бесплатно, приватно) ~3–4 ч. Качество на смеси kk/ru и 8 кГц не проверено — нужен тест на 1–2 записях.
8. **Пометка ошибок распознавания в звонках** (пример: p4-ru-003 «Салими цбе Фридом брокер за кошки» — казахское приветствие IVR, распознанное как русское): подчеркнуть фрагмент, показать вероятное прочтение, сказать ИИ, что это не речь оператора.
9. **Проверка грамотности оператора в чатах** — доказательство для «Управления диалогом». Исходный текст не менять, исправленный вариант показывать рядом.

ИИ-помощник проверяющему в апелляциях — **не делать** (ИИ склонен соглашаться с тем, кто возражает; проверяющий должен решать сам по доказательствам).
