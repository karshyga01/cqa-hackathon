# CQA — оценка качества диалогов

Прототип Conversation Quality Analytics для хакатона Freedom Broker: загрузка чатов и звонков,
оценка работы оператора по чек-листу, апелляции.

## Запуск

Нужен только [Node.js](https://nodejs.org) 18 или новее. Сторонние библиотеки не нужны.

```bash
npm start
```

Откройте **http://localhost:3000**.

Тесты:

```bash
npm test
```

### Настройки (необязательно)

Скопируйте `.env.example` в `.env` и поменяйте нужное:

| Переменная | По умолчанию | Что это |
|---|---|---|
| `PORT` | `3000` | порт сайта |
| `ORG_API_URL` | адрес DEV из задания | API организаторов без `group_id` |
| `DATA_DIR` | `data` | папка с загруженными данными |
| `ALLOWED_ORIGINS` | — | другие сайты, которым можно обращаться к API (например, Dynamics 365) |
| `AUDIO_ALLOWED_HOSTS` | `*.api.powerplatform.com,*.dynamics.com` | откуда сервер может скачивать записи звонков (только https) |

## Как загрузить диалоги

Кнопка **«Загрузить диалоги»** на странице «Диалоги». Три способа:

1. **Из API организаторов** — введите код набора (`DEV` или контрольный), нажмите «Проверить», затем «Загрузить».
   Повторная загрузка того же набора обновляет диалоги, дубликатов не будет.
2. **Файл** — JSON в формате ответа API организаторов, массив диалогов или один диалог.
3. **Вставить текст** — каждая реплика с новой строки: `00:02 operator: Здравствуйте!`.
   Роли: `client`, `operator`, `bot`, `system` (можно по-русски: клиент, оператор, бот, система).

Каждый набор хранится отдельно: контрольный набор не затрёт DEV, даже если номера диалогов совпадут.

## Карточка диалога

Клик по строке в списке открывает карточку: переписка по ролям (клиент слева, оператор справа,
бот и система — серым как контекст), важные системные события выделены («Личность подтверждена»,
«Оператор закрыл чат», «Клиент на удержании» и др. — на русском, казахском и английском).

- **Ссылка на реплику**: у каждой реплики номер `№N`; адрес `#dialog/<набор>:<id>/m-N` открывает
  карточку сразу на этой реплике (а у звонка — на этом месте записи). Клик по номеру копирует ссылку.
- **Звонки**: записи скачиваются к нам в `data/audio/` сразу после загрузки набора (у организаторов
  ссылка на mp3 живёт около часа). Плеер показывает дорожки «Клиент / Оператор / Бот», паузы и удержание;
  клик по реплике или отрезку перематывает запись, текущая реплика подсвечивается. Если запись скачать
  не удалось — кнопка «Открыть запись у организаторов».
- **Синхронизация текста и звука** (замерено на 5 звонках DEV): метка реплики — конец фразы;
  при паузе записи в mp3 остаётся 5 с тишины; браузер дополнительно подстраивает сдвиг под каждый звонок
  по громкости записи. Средняя ошибка — 0,35–0,45 с. Подробности — в `frontend/js/timeline.js`.
- Кнопки «Предыдущий / Следующий» и стрелки ← → на клавиатуре; пробел — пауза.

## Чек-листы

Страница «Чек-листы» — правила, по которым ИИ ставит баллы. При первом запуске создаётся чек-лист
из задания (8 критериев, 4 раздела, веса 10/15/20/20/15/15/5 и флаг «Грубые ошибки»).

- Критерий: название, **что проверяет ИИ** (обязательно — этот текст станет запросом к ИИ), пояснения,
  тип ответа (Да / Нет, шкала со ступенями, флаг без баллов), вес, разрешён ли N/A и при каком условии.
- **Каждое сохранение — новая версия.** Старые версии можно посмотреть и вернуть; оценка будет помнить,
  по какой версии её считали. Если чек-лист изменили в другой вкладке — сервер не даст затереть (409).
- **«Заменить критерий»** (кнопка ⟳ у строки) — на его месте появляется новый с тем же разделом и весом;
  заполнить → «Сохранить». Так выполняется контрольное задание организаторов.
- Сумма весов не 100 — только предупреждение: итог всё равно считается из 100 пропорционально.
- Ошибки показываются у поля; пока они есть, «Сохранить» неактивна. Несохранённые правки
  не потеряются при уходе со страницы — появится вопрос. Ctrl+S — сохранить.
- Правила проверки общие для браузера и сервера: `frontend/js/checklist-model.js`.

## Подсчёт баллов

ИИ только выбирает ответ по каждому критерию («Да», «Нет», N/A или ступень шкалы), баллы считает код —
`frontend/js/scoring.js` (один файл для браузера и сервера), строго по правилам PDF:

- «Да» — полный вес, «Нет» — 0; шкала — вес × (ступень ÷ верхняя ступень): 7 из 10 при весе 15 = 10,5;
- N/A исключает критерий, его вес делится между применимыми: **итог = 100 × набрано ÷ сумма весов применимых**,
  максимум всегда 100 (даже если сумма весов в чек-листе не 100);
- итог округляется до двух знаков «половина вверх» с защитой от ошибок двоичной арифметики
  (100 × 1,15 ÷ 8 в JavaScript = 14,374999…, обычное округление дало бы 14,37 вместо 14,38);
- все критерии с весом N/A → итог «не рассчитан»; грубые ошибки — отдельная отметка, итог не меняют;
- итоги по разделам: набрано и максимум после перераспределения (например, 41,18 из 47,06);
- ответ, которого нет в чек-листе (ступень вне шкалы, N/A где запрещён), не считается — возвращается понятная ошибка.

Пример: 02 = N/A, 04 = 15 из 20, 07 = Нет → 75 ÷ 85 × 100 = **88,24**; после апелляции 07 = Да → **94,12**.

## Устройство

```
frontend/          интерфейс: HTML, CSS, JS без фреймворков (можно встроить в Dynamics 365)
  js/config.js     адрес сервера (apiBase)
  js/app.js        переходы между страницами, окна, запросы к серверу
  js/dialogs.js    страница «Диалоги» и окно загрузки
  js/card.js       карточка диалога и плеер звонка
  js/timeline.js   системные события, время реплики ↔ позиция в записи (общий с тестами)
  js/checklists.js страница «Чек-листы» (редактор)
  js/checklist-model.js правила чек-листа: проверки, веса, сравнение версий (общий с сервером)
  js/scoring.js    подсчёт баллов: N/A, шкалы, итог из 100, разделы, грубые ошибки (общий с сервером)
server/
  server.js        HTTP-сервер: сайт + /api/*
  lib/orgApi.js    запрос к API организаторов
  lib/normalize.js приведение данных к одному виду, разбор текста
  lib/time.js      метки времени (MM:SS у чатов, ISO у звонков)
  lib/dialogs.js   сохранение и поиск диалогов
  lib/audio.js     скачивание записей звонков
  lib/checklists.js чек-листы с версиями
  defaults/checklist-chat.js чек-лист из задания (PDF)
  lib/store.js     хранение в JSON-файлах (атомарная запись)
data/              загруженные данные (не в git)
```

### API сервера

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/api/health` | проверка, что сервер работает |
| GET | `/api/datasets` | загруженные наборы |
| GET | `/api/dialogs?q=` | список диалогов (поиск по номеру и тексту) |
| GET | `/api/dialogs/:key` | диалог целиком, `key` = `<набор>:<conversation_id>` |
| POST | `/api/import/preview` | `{group_id}` — что в наборе, без сохранения |
| POST | `/api/import/api` | `{group_id}` — загрузить набор из API организаторов |
| POST | `/api/import/json` | `{payload, group_id?}` — загрузить из JSON |
| POST | `/api/import/text` | `{text, conversation_id?, language?, channel?}` — один диалог из текста |
| GET | `/api/dialogs/:key/audio/status` | состояние записи звонка: ready / missing / downloading / error / none |
| POST | `/api/dialogs/:key/audio/fetch` | скачать запись сейчас |
| GET | `/api/dialogs/:key/audio` | файл записи (поддерживает перемотку — HTTP Range) |
| GET | `/api/checklists` | список чек-листов |
| GET | `/api/checklists/active` | используемый чек-лист (последняя версия) |
| GET | `/api/checklists/:id` | чек-лист, последняя версия + история версий |
| GET | `/api/checklists/:id/versions/:v` | конкретная версия |
| POST | `/api/checklists` | `{from?, name?}` — новый (копия или из задания) |
| PUT | `/api/checklists/:id` | `{base_version, checklist}` — сохранить как новую версию (409 при конфликте, 422 при ошибках) |
| POST | `/api/checklists/:id/activate` | сделать используемым |
| DELETE | `/api/checklists/:id` | удалить (кроме используемого) |

Исходные метки времени сохраняются без изменений. Для показа и плеера сервер дополнительно
считает `offset_sec` — секунды от начала разговора.
