# Сравнение LLM для оценки операторов (CQA): нейтральная версия от 07.11.2026

## 0. Раскрытие

- **Кто писал.** Документ подготовлен моделью Claude, её делает Anthropic. Anthropic сама входит в число кандидатов, поэтому у автора есть конфликт интересов.
- **Как проверяли.** Все 10 групп кандидатов (Anthropic, OpenAI, Google, xAI/Mistral, DeepSeek, Qwen, Kimi/GLM, прочие китайские, региональные, хостинги открытых весов, локальные) прошли один и тот же шаблон из 9 критериев. Затем отдельный проход-верификатор перепроверил ключевые утверждения. Если верификатор что-то опроверг или исправил, в таблице стоит его поправка.
- **Глубина проверки неодинакова.** Причина не в вендорах: в сессии закончился лимит поиска. Для Anthropic, OpenAI, Google, xAI, Mistral, DeepSeek, Qwen, Kimi, GLM, Yandex, GigaChat и хостингов официальные страницы открывались напрямую. По MiniMax, ByteDance Seed, Baidu и Tencent перепроверка почти не состоялась: данные взяты из сниппетов и агрегаторов. Локальная группа описана в основном по памяти и по проверке самого ноутбука. Поэтому «не подтверждено» в этих строках частично означает неполную проверку, а не слабость вендора.
- **Победителя нет.** Правила отбора записаны до того, как их применили. Итог документа — список кандидатов для теста на наших данных.
- **Главный факт:** ни у одной текущей API-модели нет независимого результата на казахском. Все казахские цифры ниже относятся к старым версиям (GPT-4o, DeepSeek V3, Claude 3.5 Sonnet, Gemini 1.5 и т.п.). Средние по KazMMLU смешивают казахские и русские вопросы. Цифры взяты из версии v2 статьи; в v1 они другие.

**Обозначения.** «н/д» — нет данных. «н/п» — не подтверждено. «стар.» — результат старой версии модели; приводится для сведения и в ранжировании не участвует. Цена одной оценки = (5 000 × цена входа + 3 000 × цена выхода) / 1 000 000. Во всех моделях с рассуждением оно оплачивается как выход. Там, где рассуждение нельзя отключить, 3k выходных токенов — допущение, реальный расход может быть больше.

## 2. Фильтр

### 2.1 Правила (записаны до применения)

**Жёсткие требования.** «?» означает «не подтверждено». Такой кандидат не исключается, но опускается в уровне.

- **H0. Применимость.** Контекст вмещает около 7k на входе и 3k на выходе. Лицензия разрешает использование брокером.
- **H1. Доступ.** «да»: официальная страница называет Казахстан, есть локальное юрлицо или регистрация не нужна (локальный запуск). «?»: запрета не нашли, подтверждения тоже нет. «нет»: явный запрет или нет пути запуска.
- **H2. Структурированный вывод.** Возможные оценки:
  - **A** — гарантия схемы с описанным механизмом (constrained decoding или грамматика);
  - **A′** — документация заявляет «строго по схеме», но механизм не описан;
  - **B** — есть только JSON mode, валидацию и повтор делает наш код;
  - **?** — для этой модели не задокументирован даже JSON mode.

  Проходят A, A′ и B.
- **H3. Данные.** «да»: официальный документ говорит, что данные API по умолчанию не идут на обучение, и указан срок хранения или есть ZDR; локальный запуск тоже «да». «?»: документы противоречат, умолчание не указано или есть только пересказ. «нет»: данные по умолчанию идут на обучение.
- Закон 94-V не используется как фильтр. Любой API, включая, по всей видимости, Yandex, означает трансграничную передачу данных одинаково для всех вендоров. Разрешать её или нет, решают организаторы и юристы.

**Уровни.** Если хотя бы одно «нет», кандидат исключается. Уровень 1: всё пройдено. Уровень 2: внутри уровня сортировка по числу «?».

**Отбор внутри вендора.** Сначала берётся модель с лучшим уровнем. При равенстве — старшая модель, у которой оценка стоит не больше $0.05.

**Ранжирование внутри категории** идёт строго по порядку:

- **R1.** Независимый результат на казахском или русском **для этой же версии**. Он учитывается, только если модель в верхней половине своего лидерборда. Результат в нижней половине ставит модель ниже, чем «н/д».
- **R2.** Уровень H2: A выше A′, A′ выше B.
- **R3.** Скорость: позволяют ли документированные лимиты и расчётная задержка прогнать около 65 диалогов примерно за 10 минут.
- **R4.** Цена. Разница меньше $0.05 за оценку не учитывается: 100 оценок у всех стоят меньше $20.
- **R5.** Трудозатраты на интеграцию. Этот фактор только упорядочивает кандидатов, но никого не отсекает.

**Места.** Пять категорий (западные закрытые, китайские, открытые веса на хостинге, региональные, локальные) получают по одному месту. Два дополнительных места достаются кандидатам, которые равны победителю своей категории по R1–R4. Если претендентов больше двух, приоритет у API-категорий: скорость и качество локального варианта отвечает прогон одной 4B-модели.

### 2.3 Отбор по категориям

- **Западные закрытые.** Внутри вендора по правилу выходят Sonnet 5.5, GPT-6.1 Sol и Gemini 4 Argon. По R1 у всех трёх «н/д»; по R2 у всех A; по R3 лимиты достаточны у всех; по R4 у всех $0.040. **Полная ничья.** R5 только упорядочивает: Sol (родной OpenAI-формат), Argon (есть OpenAI-совместимый эндпоинт в бете), Sonnet (OpenAI-совместимый эндпоинт Anthropic «не для продакшена» и игнорирует strict, поэтому нужен родной SDK). Основное место получает Sol. Argon и Sonnet получают дополнительные места как равные по R1–R4.
- **Китайские.** Уровня 1 нет ни у кого. С одним «?» остаются Qwen и Seed. По R1 у обоих «н/д». По R2 Qwen (A′) выше Seed (?). Внутри Qwen по правилу выходит **qwen3.8-max**.
- **Открытые веса на хостинге.** С одним «?» остаются несколько моделей. По R1 у V4.1-Flash 0.581 (2-е место MERA), у Qwen3.8-27B 0.394 (19-е место). Проходит **DeepSeek V4.1-Flash на Together**. Побочный эффект: данные не уходят в КНР.
- **Региональные.** Уровень 1 только у **YandexGPT Pro 5.1**. Alice AI LLM опускается по H2.
- **Локальные.** У Gemma 3 4B, Qwen3-4B и Gemma 4 E2B по R1 «н/д», а Qwen3.5-4B находится в нижней половине MERA. 8B-модели проигрывают по R3. По R5 выигрывает **Gemma 3 4B**: она уже скачана. Qwen3-4B тоже равна по R1–R4, но дополнительные места уже отданы API-категориям.

## 4. План теста (bake-off)

**Шаг 0. Проверка доступа, по 15 минут на провайдера.** Зарегистрироваться и пополнить баланс казахстанской картой. Записать результат. Это закрывает «?» в H1, и фильтр после этого применяется заново.

**Эталонный набор: 16 диалогов.** Состав: 5 русских чатов, 5 казахских или смешанных kk/ru, 3 английских, 3 звонка с ошибками распознавания речи. Двое людей размечают все 8 критериев независимо и **до** того, как увидят ответы моделей: ответ, пояснение, номера реплик и цитату. Расхождения разбираются вместе. Согласие двух людей фиксируется как потолок, выше которого модели не прыгнут. Персональные данные (имена, телефоны, ИИН, номера счетов) обезличиваются одинаково и до разметки, чтобы цитаты по-прежнему совпадали с текстом.

**Одинаковые условия для всех моделей.**

- Один системный промпт на русском. Казахский промпт не использовать: у DeepSeek V3 он снижал результат.
- Одна схема по наименьшему общему знаменателю: object, string, integer, array, enum, required для всех полей, additionalProperties:false. Без minLength/maxLength, pattern, oneOf/anyOf и $ref: часть провайдеров их не поддерживает или молча отбрасывает.
- max_output_tokens не меньше 16k, чтобы рассуждение не обрезало JSON.
- temperature = 0 там, где это разрешено. Где temperature зафиксирован или запрещён (Claude, Kimi), это фиксируется в отчёте.
- effort оставить по умолчанию и тоже записать.
- По 2 прогона на модель.

**Метрики.** Казахская часть и звонки считаются отдельно.

1. Совпадение с людьми по каждому критерию: точное совпадение, для шкал 0/5/10/15/20 ещё и среднее отклонение; каппа Коэна.
2. Матрица путаницы «Нет ↔ N/A» по каждому критерию.
3. Полнота и точность флага грубой ошибки.
4. Отклонение итогового балла (считает наш код) от балла людей.
5. Сбои JSON: не парсится, не проходит схему, отказ модели, обрезка. Считаются до одного повтора и после.
6. Выдуманные ссылки: номер реплики не существует или цитаты нет в указанной реплике (проверка по подстроке после нормализации пробелов).
7. Стабильность: доля решений, которые совпали в двух прогонах.
8. Задержка p50/p95 и общее время на 16 диалогов при параллельном запуске, с пересчётом на 65.
9. Реальная стоимость по полям usage, включая токены рассуждения.

**Ограничение по точности.** 16 диалогов × 8 критериев = 128 решений, доверительный интервал около ±8 п.п. Разницу меньше примерно 10 п.п. считать шумом и указывать абсолютные числа. Правило выбора нужно записать до прогона, например: «основная метрика — совпадение по всем 128 решениям; условия — 0 сбоев JSON после повтора, не больше 5% выдуманных ссылок, пересчитанное время на 65 диалогов не больше 10 минут». Сбои JSON, время и стоимость можно дополнительно измерить на всех 65 диалогах без разметки.

**Бюджет.** На одну оценку по семи моделям уходит $0.040 × 3 + $0.028 + $0.0051 + $0.0525 + $0 ≈ $0.206. За 32 прогона (16 диалогов × 2) это ≈ $6.6, а при удвоенном выводе из-за рассуждения ≈ $11.

**Маршрут через один ключ.** OpenRouter закрывает открытые модели; эндпоинты DeepSeek V4.1-Flash, V4-Pro, Qwen3.5-397B, Kimi K2.6 и Llama 4 подтверждены. Есть ли там GPT-6.1 Sol, Sonnet 5.5, Argon и qwen3.8-max, не проверено. Yandex и локальная модель всё равно подключаются отдельно.

**Оговорка про данные при работе через OpenRouter.** Одна и та же модель может уйти к разным провайдерам в разных странах, с разными сроками хранения и разным квантованием. Поэтому нужно:

- закреплять провайдера (provider.order, allow_fallbacks:false);
- ставить require_parameters:true;
- включать фильтр «только ZDR».

Без закрепления результаты теста не сравнимы между собой, а данные могут уйти куда угодно. Сам OpenRouter по документации не хранит промпты без явного согласия; доступ к нему из KZ (оплата через Stripe в USD или криптовалютой) не проверен. Отправлять разговоры клиентов любому внешнему провайдеру можно только с разрешения организаторов.

## 5. Что осталось неподтверждённым

1. **Казахский язык.** Для текущих версий всех API-моделей независимых данных нет. Belebele kaz_Cyrl, ISSAI/KazLLM-лидерборды, KazQAD и MMLU-ProX для текущих моделей не проверялись: кончился лимит поиска. «Н/д» значит «не найдено», а не «отсутствует».
2. **Русский язык.** Лидерборд MERA прочитан один раз (47 записей). Записи «Gemini 3.7 Flash» нет в текущем списке моделей Gemini API.
3. **Оплата казахстанской картой** не подтверждена ни у одного зарубежного провайдера. Списков поддерживаемых стран нет у xAI, Mistral, DeepSeek, Kimi, Z.ai, MiniMax, Baidu, Tencent, Together, Fireworks, OpenRouter и Groq.
4. **Китайские вендоры.**
   - Seed: ID моделей, цены, работа json_schema на конкретной модели.
   - MiniMax и ERNIE: цены противоречат друг другу.
   - Hy3: цены только из агрегаторов.
   - Политика данных MiniMax, Baidu и Tencent не проверена. Эта группа проверена хуже всех.
5. **Qwen:** работает ли strict json_schema в регионе Сингапур.
6. **Mistral:** механизм строгой схемы и точный ID Large 4.
7. **Yandex:**
   - в каком регионе идёт инференс AI Studio для клиентов из KZ;
   - поддерживает ли json_schema Alice AI LLM;
   - базовый URL OpenAI-совместимого API;
   - процедура онбординга.
8. **GigaChat:** договор с юрлицом из KZ; утверждение LiteLLM, что strict-режим эмулируется через function calling.
9. **Оплата токенов рассуждения как выхода:** не указано явно у Mistral, DeepSeek, GLM и прочих китайских вендоров; у xAI подтверждено частично.
10. **Лимиты для новых аккаунтов:** у Anthropic Evaluation tier не опубликован; у Google лимиты по моделям показываются только в консоли; у Mistral, Z.ai, Together, Groq и OpenRouter не найдены.
11. **Локальный запуск:**
    - вся скорость — расчёт, а не замер;
    - помещается ли Gemma 3 4B с vision-частью в 4 ГБ;
    - значение num_ctx в Ollama по умолчанию (без явной настройки диалог молча обрежется);
    - поддерживает ли Ollama Gemma 4.
12. **Хостинги:** у какого провайдера на OpenRouter какое квантование и какая сборка.
13. **Юридическая часть:** соответствие закону 94-V ни для одного варианта не оценивалось.
